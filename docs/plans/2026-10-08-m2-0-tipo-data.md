**Situação hoje (v0.1.1, conferido em 08/10/2026 com um CSV de 40 linhas):** `data` com repetições → **nominal** (tabela de 28 "categorias"); `hora` e `data_hora` sem repetição → **identificador** com o motivo errado "Parece um código: 100% dos valores são únicos.".

### Regras que o código implementa
- **Formatos reconhecidos** (padrões explícitos, nada de `pd.to_datetime` "adivinhando" — evita tomar códigos e números por datas):
  | Formato | Exemplos | Motivo |
  |---|---|---|
  | `DD/MM/AAAA`, `DD-MM-AAAA`, `DD.MM.AAAA` (dia/mês com 1 ou 2 dígitos; ano com 4) | 07/10/2026, 7-10-2026 | "Datas no formato DD/MM/AAAA (ex.: 07/10/2026)." |
  | `AAAA-MM-DD` (ISO) | 2026-10-07 | "Datas no formato AAAA-MM-DD (ex.: 2026-10-07)." |
  | qualquer data acima + ` HH:MM[:SS]` (ou `T` no ISO) | 07/10/2026 08:30, 2026-10-07T08:30:00 | "Datas com horário (ex.: 07/10/2026 08:30)." |
  | `HH:MM[:SS]` (00–23 h) | 08:30, 17:05:12 | "Horários (ex.: 08:30)." |
  | Células de data/hora do XLSX (dtype `datetime64` ou objetos `datetime`/`date`/`time`) | — | "Datas da planilha (ex.: 07/10/2026)." |
- **Limiar:** a coluna é `data` se **≥ 90%** dos valores válidos casam com **um mesmo** formato e viram data válida (`limiar_data = 0,9` em `config.py`, mesmo valor do `limiar_numerico`, D48). Os demais são tolerados (como no tipo misto).
- **Dia ou mês primeiro** (`DD/MM` × `MM/DD`): padrão brasileiro, dia primeiro. Se nenhum valor tem o 1º campo > 12 e algum tem o 2º campo > 12, a coluna é lida como mês primeiro e o motivo diz "Datas no formato MM/DD/AAAA (ex.: 10/27/2026)."; se os dois campos passam de 12 em valores diferentes, não é data.
- **Ordem na cadeia:** `_vazia` → **`_data`** → `_identificador` → `_binaria` → … Assim uma data única por linha não vira "código". Colunas numéricas (≥ 90% viram número) nunca são testadas como data (um `20261007` continua número).
- **Fora das análises:** `GET /analise` e `/posicao` de uma coluna `data` → 400 `COLUNA_IGNORADA` com a mensagem "A coluna {col} tem datas e fica fora das análises." e a sugestão "Mude o tipo na etapa Variáveis se ela tiver valores para analisar."; o relatório não cria seção para ela; na tela 4 e na Bivariada ela não aparece nos seletores.
- **Limpeza:** faltantes valem para `data` (sugestão = moda, como categóricas); duplicados comparam a coluna de data (D50 só tira identificadores); fora de faixa, grafias e tipo misto não se aplicam (não muda nada no diagnóstico atual, que só olha numéricas e categóricas). Valores que não viraram data **não** aparecem na limpeza neste bloco (registrado como limitação na spec 03).
- **Ajuste manual:** para `data` exige ≥ 90% reconhecíveis, senão `TIPO_INCOMPATIVEL` "Esta coluna não tem datas ou horários que dê para reconhecer."; de `data` pode ir para nominal, ordinal, binária (se 2 valores) e identificador; para discreta/contínua continua bloqueado ("Esta coluna tem textos; não pode ser numérica.").
- **Prévia e exemplos:** as células continuam como estão no arquivo (texto); datas do XLSX aparecem como `AAAA-MM-DDTHH:MM:SS` hoje (`tabela.celula`) — passam a sair como `07/10/2026` / `07/10/2026 08:30` / `08:30` (formato pt-BR), também nos `exemplos` do `TipoColuna`.
- **Fora do escopo:** separar mês, dia da semana, ano etc. em colunas novas; análise de séries temporais; datas por extenso ("7 de outubro de 2026").

### Tarefa 2: reconhecer datas e horários (`compartilhado/datas.py`)

**Arquivos:** criar `app/compartilhado/datas.py`, `tests/compartilhado/test_datas.py`

API:
```python
type FormatoData = Literal["dd/mm/aaaa", "mm/dd/aaaa", "aaaa-mm-dd", "data_hora", "hora", "planilha"]


@dataclass(frozen=True, slots=True, eq=False)
class LeituraDatas:
    formato: FormatoData
    valores: pd.Series          # datetime64 (NaT onde não casou)
    proporcao: float            # fração dos válidos que virou data
    exemplo: str                # 1º valor válido como está no arquivo


def reconhecer_datas(serie: pd.Series) -> LeituraDatas | None:
    """Melhor formato de data/hora da série, ou None se nenhum valor casar."""


def formatar_data(valor: object) -> str:
    """07/10/2026 · 07/10/2026 08:30 · 08:30 (pt-BR), para prévia e exemplos."""
```
- Um padrão (`re.Pattern`) e um `format=` do `pd.to_datetime(..., errors="coerce")` por formato, numa tabela (`FORMATOS: tuple[FormatoTexto, ...]`); `reconhecer_datas` testa todos e fica com a maior proporção (empate: ordem da tabela). Dia/mês decidido por `_dia_primeiro(partes)` (regra acima).
- dtype `datetime64` (XLSX) ou objetos `datetime`/`date`/`time` → `"planilha"`, proporção = fração não nula.
- Datas impossíveis (31/02/2026, 25:00) não contam (o `to_datetime` com `errors="coerce"` dá `NaT`).

**Testes (falham):**
```python
@pytest.mark.parametrize(
    ("valores", "formato"),
    [
        (["07/10/2026", "8/10/2026", "31/12/2025"], "dd/mm/aaaa"),
        (["10/27/2026", "10/28/2026", "1/2/2026"], "mm/dd/aaaa"),
        (["2026-10-07", "2026-10-08"], "aaaa-mm-dd"),
        (["07/10/2026 08:30", "2026-10-07T17:05:12"], "data_hora"),
        (["08:30", "17:05:12", "0:15"], "hora"),
    ],
)
def test_reconhece_o_formato(valores: list[str], formato: str) -> None:
    leitura = reconhecer_datas(pd.Series(valores))
    assert leitura is not None and leitura.formato == formato and leitura.proporcao == 1.0


def test_datas_impossiveis_nao_contam() -> None:
    leitura = reconhecer_datas(pd.Series(["31/02/2026", "07/10/2026"]))
    assert leitura is not None and leitura.proporcao == 0.5


@pytest.mark.parametrize("valores", [["1,62", "1,78"], ["20261007", "20261008"], ["Goiânia", "Anápolis"],
                                     ["13/14/2026", "07/10/2026"]])
def test_nao_toma_outros_valores_por_data(valores: list[str]) -> None:
    leitura = reconhecer_datas(pd.Series(valores))
    assert leitura is None or leitura.proporcao < 0.9


def test_colunas_de_data_do_xlsx() -> None:
    serie = pd.Series(pd.to_datetime(["2026-10-07", "2026-10-08"]))
    assert reconhecer_datas(serie).formato == "planilha"


@pytest.mark.parametrize(
    ("valor", "texto"),
    [(pd.Timestamp("2026-10-07"), "07/10/2026"), (pd.Timestamp("2026-10-07 08:30"), "07/10/2026 08:30"),
     (datetime.time(8, 30), "08:30")],
)
def test_formatar_data(valor: object, texto: str) -> None:
    assert formatar_data(valor) == texto
```

  def _data(coluna: ColunaLida) -> Classificacao | None:
